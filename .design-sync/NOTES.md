# design-sync notes — @n3wth/ui

## Repo-specific gotchas

- **The library build strips Tailwind utilities from the published CSS.** `npm run build`'s
  postbuild step reads raw `src/styles.css` and regex-strips `@import 'tailwindcss';` before
  writing `dist/styles.css` (consumers regenerate utilities in their own Tailwind v4 app via
  `@import '@n3wth/ui/theme'`). So `dist/styles.css` — and anything sourced from it — carries
  ZERO generated utility CSS. Every plain-Tailwind className renders unstyled.
  **Fix (in place):** `cfg.cssEntry` points at a compiled stand-in for a consumer's Tailwind
  build: `.design-sync/tailwind-entry.css` (`@import '../src/styles.css'` + `@source ../src/**/*.tsx`,
  NO demo font override) compiled by `@tailwindcss/cli@4.1.18` to `.design-sync/.cache/compiled.css`.
  The compile is folded into `cfg.buildCmd`, so re-syncs regenerate it. Verified: the compiled
  output contains `.rounded-full`, `.inline-flex`, `.bg-[var(--color-white)]`, `.border-t`, etc.

- **Dark-first DS, but the preview harness renders on a white body.** `--color-bg` is #08090b and
  the DS intentionally ships NO `body` background (the consuming app paints it). The card harness
  (`lib/emit.mjs`) hardcodes `body{background:#fff}`, so dark-first components (a white primary
  Button, ink-on-dark text) render invisible on white. `N3wthProvider` alone does NOT paint a
  surface (Astryx `<Theme>` only injects tokens).
  **Fix (in place):** `cfg.provider` chains a repo-owned `PreviewSurface` (paints `--color-bg` /
  `--color-ink`, added via `cfg.extraEntries: ['./.design-sync/preview-provider.tsx']`) OUTSIDE
  `N3wthProvider` (mode `dark`, supplies Astryx tokens for Separator/Skeleton/Card surface).

- **PREVIEW-AUTHORING CONVENTION (hard rule): inline styles only in `previews/*.tsx`, never
  Tailwind classNames.** `@source` is scoped to `src/**/*.tsx` on purpose so `cssEntry` compiles
  ONCE and stays valid across a parallel authoring wave (subagents can't rebuild the shared
  bundle). A className in a preview is not scanned → renders unstyled. Style preview wrapper
  markup with inline `style={}`; the real components already carry their classNames from `src`.

- **Fonts live in `public/fonts/` with absolute `/fonts/…` @font-face urls** the converter can't
  resolve on its own → `[FONT_DANGLING]`. Fixed via `cfg.extraFonts` listing the woff2 files so
  they copy into `fonts/` and the url()s rewrite.

- **`PreviewSurface` is a `<div>` wrapper — it does NOT cover portaled content.** Components
  that render via `createPortal(..., document.body)` (Tooltip's popup; anything similarly
  portal-based like a future Popover/Menu) escape the wrapper's dark background entirely,
  because the portal target is `document.body`, not a DOM descendant of the wrapper div.
  `Modal` happens to need no fix (its own panel/backdrop are opaque-dark by construction), but
  don't assume the shared provider covers portals in general.
  **Fix (per-preview, not config-level):** darken `document.body` directly in a `useEffect` on
  mount (fresh page load per `?story=` capture, so no cleanup needed) — see `Tooltip.tsx`'s
  `Stage` component for the reference pattern.

- **Forcing a hover-only component open for static capture: dispatch `mouseover`, not
  `mouseenter`.** `mouseenter` doesn't natively bubble, and React's synthetic `onMouseEnter` is
  derived from listening for the bubbling `mouseover` event — a `new MouseEvent('mouseenter', {bubbles:true})`
  silently does nothing (no error, just no open state). Dispatch `new MouseEvent('mouseover', {bubbles:true})`
  on the trigger ref instead. General pattern for any future hover/focus-only trigger component
  (Popover, Menu, etc.), not just Tooltip.

- **Two confirmed component-source bugs found during preview authoring (not fixable from
  `previews/`, not a design-sync/CSS-pipeline problem)** — this is why `NavLink` and
  `AnimatedText` remain flagged not-fully-good:
  - `NavLink` (`src/molecules/NavLink/NavLink.tsx`): the `pill`+`isActive` branch uses
    `bg-[--color-white] border-[--color-white]` — bare custom-property bracket syntax with no
    `var()` wrapper. Confirmed via grep this exact class string never appears in
    `.design-sync/.cache/compiled.css` even though `@source` correctly scans `src/**/*.tsx` — the
    bracket-without-`var()` form doesn't get generated by Tailwind. Result: the pill has no
    background, and its text color is deliberately set to `var(--color-bg)` (dark, meant to sit
    on a white pill) — dark-on-dark, fully invisible. Real fix: `bg-[var(--color-white)]
    border-[var(--color-white)]` in the component source. Only 3 occurrences of this syntax
    exist in all of `src/` and all are in this one file.
  - `AnimatedText` (`src/atoms/AnimatedText/AnimatedText.tsx`): defines an `animationStyles` map
    with both `initial` and `animate` classNames per animation type, but the render function only
    ever applies `initial` — `animate` is dead code, never referenced anywhere. There's also no
    `@keyframes`/utility named `animate-fade-up` (or the other 3 variants) in `src/styles.css`.
    The component structurally never transitions out of its initial (invisible, `opacity-0`)
    state — not a hard-to-screenshot mid-animation timing issue, it never completes regardless of
    when you screenshot it. All previewed cells render fully blank at full resolution. Real fix
    belongs in the component (wire up the `animate` class swap, on-mount or via
    `IntersectionObserver` per `animateOnScroll`, plus the missing keyframes).

- **Repo docs/demo examples lag the shipped component API in several places** — sanity-check any
  ported prop against the current `.d.ts` before trusting a docs/demo snippet (per §4.2's
  guidance): `Footer`'s `demo/App.tsx`/`OrganismsSection.tsx` pass `theme`/`onThemeToggle`, which
  don't exist on `FooterProps`; `docs/components.md` shows `AnimatedText` with `text`/`stagger`
  props that don't exist (real props: `children`, `animation`, `delay` in ms, `duration`, `as`,
  `animateOnScroll`); `OrganismsSection.tsx`'s `<Section variant="alternate">` — `variant` isn't on
  `SectionProps` (`size`/`spacing`/`container` only); `MoleculesSection.tsx`'s
  `<Icon name="external" />` — the real `IconName` union has `external-link`, not `external`.

- **Concurrent unscoped `package-capture.mjs` runs churn the shared scratch dir but not durable
  state.** `ds-bundle/_screenshots/review/` (raw PNGs + tiled sheets) is shared, non-namespaced
  scratch — during parallel authoring waves, one agent's unscoped capture run visibly prunes/
  replaces another's files there. This is expected/harmless churn on gitignored, regenerated-
  every-run scratch; the durable verdict state (`.design-sync/.cache/review/*.grade.json`) is
  untouched by another agent's run. Always scope `package-capture.mjs --components <mine>` in a
  parallel wave (per the subagent hard rules) — an unscoped run is what causes the churn.

- **Avatar's broken-image fallback is deliberately unauthored.** It depends on an async
  `<img onError>` firing before the capture's screenshot — a timing race, not a static-render
  state. Used an inline `data:image/svg+xml` data URI for the "with photo" story instead of a
  network image URL so capture never depends on network access or timing.

- **Dropdown's open-menu state has no controlled/`defaultOpen` prop** — it's internal
  `isOpen` state toggled only by a real click. Current previews only cover states that render
  correctly closed (`Default`/`Selected`/`Multi`/`Searchable`/`Disabled`). Adding an open-menu
  export is a real follow-up opportunity: it would need
  `cfg.overrides.Dropdown: {"cardMode": "single", "viewport": "WxH"}` plus a preview-only
  force-open wrapper (same idea as Tooltip's `OpenTooltip`) — not applied yet since no such
  export exists today; add both together when someone authors it.

## Known render warns (triaged legitimate — a warn NOT here on re-sync is new)

- `[TOKENS_MISSING]` for `--x-*` names: Astryx CSS-in-JS runtime vars, set at render time by the
  Astryx `<Theme>`; expected absent from the static stylesheet. Also `--color-syntax-*` (CodeBlock
  applies these via inline `style={}`).
- `[GRID_OVERFLOW]` resolved via presentation overrides (see config `overrides`): Toast/Hero/
  Progress/Separator/Skeleton/Card/Footer/Nav → `column`; Modal/Tooltip → `single` (Tooltip's
  popup is a `fixed`/portal escape — `column` alone doesn't fix it, only `single` is fully exempt
  by construction; `primaryStory: "Positions"` since it demonstrates all 4 placements in one cell).
- `[FONT_DANGLING]` for "mona sans"/"geist sans"/"geist mono" (one representative url per family)
  is a **validator false positive, not a real gap** — verified the actual files
  (`MonaSans-Variable.woff2`, `Geist-Regular.woff2`, `GeistMono-Regular.woff2`, etc.) ARE present
  in `ds-bundle/fonts/`. Root cause: `fonts/fonts.css`'s `@font-face` `url()`s are intentionally
  root-absolute (`/fonts/MonaSans-Variable.woff2` — meant to resolve against the site root when
  the DS is actually served), but `package-validate.mjs`'s dangling-check does
  `resolve(dirname(cssFile), url)`, and Node's `path.resolve()` discards the first argument
  whenever the second is itself absolute — so it checks for a literal `/fonts/...` at the OS
  filesystem root, which naturally never exists. Every family in `fonts.css` uses this same
  absolute-url pattern, so this warn is structural to the repo's font setup and will re-fire on
  every sync — re-verify by checking `ds-bundle/fonts/` before assuming it's a new problem.

## Re-sync risks (what can silently go stale)

- **`cfg.cssEntry` compiled file is a build artifact** (gitignored under `.design-sync/.cache/`).
  It MUST be regenerated by `cfg.buildCmd` before every converter run, else previews render
  unstyled again. The durable input is `.design-sync/tailwind-entry.css` (committed).
- **`PreviewSurface` is a design-sync-owned shim** (`.design-sync/preview-provider.tsx`, committed)
  tied to the DS's dark-first token names (`--color-bg`, `--color-ink`). If those token names
  change in `theme.css`, update the shim.
- **The upstream build stripping Tailwind is intentional** (not a bug to "fix" in the library).
  If the library ever ships utilities in `dist/styles.css` directly, revisit whether `cssEntry`
  should point back at `dist/styles.css`.
- Toolchain assumed: `@tailwindcss/cli@4.1.18` (matches repo's `tailwindcss` devDep) fetched via
  `npx`; needs network on a cold cache. Node 22, npm.
